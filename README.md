# Finbert-Sentiment-Rag

An end-to-end pipeline that tests whether financial news sentiment carries any
real relationship to stock price movement — at daily and intraday resolution —
and wraps the results in a retrieval-augmented (RAG) chatbot and a Streamlit
dashboard.

This project is built as an **honest empirical exercise**, not a "sentiment
predicts stocks" pitch. Every test is reported regardless of outcome, baselines
are included everywhere a model is evaluated, and a dedicated section checks
for the most likely artifact explanation before any effect is interpreted as
real. See the notebook for how each test is reasoned about, and treat any
single run's output as one sample of a noisy, short-window estimate rather
than a fixed finding — the underlying news window is tied to whenever the
notebook is run.

## What the pipeline does

1. **Collect price data** — daily and hourly OHLC bars for a fixed set of
   tickers via `yfinance`.
2. **Collect news** — headlines per ticker via the NewsAPI `everything`
   endpoint, pulled in date-bucketed windows with retry/backoff and
   incremental per-ticker saves.
3. **Clean & entity-link** — drop empty/duplicate titles, confirm each
   article is actually about the ticker's company (spaCy NER + Wikidata QID,
   with an alias-match fallback), and filter out articles where the company
   is only the *source* of a rating on some other company.
4. **Fine-tune FinBERT** on the Financial PhraseBank dataset for domain
   adaptation, then score every collected headline.
5. **Build a labeled daily dataset** — headlines are matched to the next
   trading day via `merge_asof`, with a strict date-based (not random)
   train/test split to avoid leakage.
6. **Test sentiment vs. next-day direction** — Welch's t-test, reported for
   both the full sample and a non-neutral-only subset.
7. **Compare models against an honest baseline** — Logistic Regression,
   Random Forest, and Gradient Boosting, evaluated with `TimeSeriesSplit`
   against an always-predict-majority-class baseline.
8. **Intraday test** — headlines matched to the next available hourly bar
   after publish time, and the same significance test re-run at multiple
   horizons (1h, 4h, ~1 trading day).
9. **Effect size & consistency check** — Cohen's d alongside the p-values,
   plus a check for whether any effect is consistent across tickers or driven
   by one or two.
10. **Artifact check** — tests whether "positive" articles are simply
    published *after* a price has already moved (reporting on a move rather
    than predicting one), which would undercut any apparent effect above.
11. **RAG explainability layer** — a FAISS index over the news corpus, queried
    through a local Ollama model so you can ask natural-language questions
    about *why* sentiment looks the way it does for a given ticker/window.
12. **Streamlit app** — a unified dashboard combining price charts,
    sentiment analytics, and the RAG chatbot.

## Project structure

```
.
├── financial.ipynb      # full pipeline, sections 0–16
├── app.py                # Streamlit dashboard (written out by the notebook)
├── requirements.txt
├── .env.example
├── data/                  # generated by the notebook (gitignored by default)
└── models/                # fine-tuned FinBERT + FAISS index (gitignored)
```

## Setup

1. Clone the repo and create a virtual environment.
2. `pip install -r requirements.txt`
3. `python -m spacy download en_core_web_sm`
4. Copy `.env.example` to `.env` and add your own `NEWSAPI_KEY`
   (free tier at https://newsapi.org).
5. Open `financial.ipynb` and run top to bottom. This will populate `data/`
   and `models/`.
6. For the RAG section, have [Ollama](https://ollama.com) running locally
   with the model pulled: `ollama pull llama3.1:8b`.
7. To launch the dashboard once the notebook has been run at least once:
   ```
   streamlit run app.py
   ```
   (run this from the same directory that contains `data/` and `models/`).

## Notes on reproducibility

- NewsAPI's free tier only covers roughly the last 30 days, so the
  news/price window is always relative to "today" rather than a fixed
  historical range. Re-running the notebook on a different day pulls a
  different underlying sample.
- The fine-tuned FinBERT model and FAISS index are cached to disk after the
  first run — later cells detect and reuse them instead of retraining.
- Any statistical results in this pipeline should be read as a single-run
  estimate over a small, noisy window, not a stable claim about markets.

## Tech stack

pandas / numpy / scikit-learn / scipy, PyTorch + Hugging Face Transformers
(FinBERT fine-tuning), spaCy (entity linking), sentence-transformers + FAISS
(retrieval), Ollama (local LLM for RAG), yfinance + NewsAPI (data collection),
Streamlit (dashboard).
